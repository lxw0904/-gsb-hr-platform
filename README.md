# 澄明 HR 人力资源管理平台

一个可完全在本地运行的前后端分离人力资源管理平台。前端负责页面与交互，后端只提供 RESTful API，数据持久化到本地 SQLite 单文件，不依赖云服务、Redis、消息队列或微服务。

## 1. 项目结构

```text
.
├─ server/                 # Node.js + Express + SQLite API
│  ├─ data/                # 运行时自动生成 SQLite 文件（已忽略提交）
│  ├─ src/
│  │  ├─ routes/           # REST API 路由
│  │  ├─ scripts/          # 数据库初始化命令
│  │  ├─ app.js            # Express 应用与统一错误处理
│  │  ├─ db.js             # SQLite 连接
│  │  ├─ schema.js         # 建表 SQL
│  │  ├─ seed.js           # 演示数据
│  │  └─ index.js          # API 启动入口
│  └─ package.json
├─ web/                    # Vue 3 + Vite + Element Plus
│  ├─ src/
│  │  ├─ views/            # 业务页面
│  │  ├─ layouts/          # 侧边栏 + 顶栏布局
│  │  ├─ components/       # 通用组件
│  │  ├─ api/              # fetch 统一封装
│  │  └─ stores/           # 轻量登录状态
│  ├─ vite.config.js       # /api 代理到后端 3000 端口
│  └─ package.json
└─ README.md
```

## 2. 环境要求

- Node.js `>= 22.5.0`，推荐 Node.js 24 LTS。
  - 后端使用 Node 内置 `node:sqlite`，无需安装原生 SQLite npm 包，也不需要单独安装 SQLite 命令行工具。
- npm `>= 10`。安装 Node.js 时会一并安装 npm。
- 浏览器推荐最新版 Chrome、Edge 或 Firefox。

可在终端确认：

```bash
node -v
npm -v
```

> 本项目不依赖任何公网服务。依赖安装完成后，日常运行完全离线；SQLite 数据只保存在本机 `server/data/hr.sqlite`。

## 3. 本地启动

前后端是两个独立子项目，必须使用两个终端分别启动。

### 3.1 启动后端

```bash
cd server
npm install
npm run init-db
npm run dev
```

后端默认地址：`http://127.0.0.1:3000`

首次启动服务也会自动建表并灌入演示数据；`npm run init-db` 可手动确认初始化结果。已有数据库时不会覆盖数据。

### 3.2 启动前端

另开一个终端：

```bash
cd web
npm install
npm run dev
```

前端默认地址：`http://127.0.0.1:5173`

前端所有 `/api` 请求由 Vite 开发服务器代理到 `http://127.0.0.1:3000`，没有写死后端域名，也没有通过 CORS 插件绕过浏览器限制。

### 3.3 默认演示账号

| 角色 | 用户名 | 密码 | 数据范围 |
|---|---|---|---|
| 管理员 | `admin` | `admin123` | 全部组织数据、用户角色、审计日志、重置演示数据 |
| HR | `hr` | `hr123` | 员工、组织、考勤、请假审批、薪酬维护 |
| 普通员工 | `employee` | `employee123` | 仅本人档案、考勤、请假和工资条 |

## 4. 数据库与演示数据

- SQLite 文件：`server/data/hr.sqlite`
- 服务重启后数据仍保留。
- 普通启动不会覆盖已有数据。
- 重置为初始演示数据：

```bash
cd server
npm run reset-db
```

也可以在管理员页面进入“用户与角色”，点击“重置演示数据”。页面和命令重置都会清空现有业务数据并恢复演示账号。命令重置前建议先停止后端服务，避免本机文件同时写入。

### 自定义配置（可选）

环境变量均有本地可用默认值，不配置也能运行：

| 环境变量 | 默认值 | 说明 |
|---|---|---|
| `PORT` | `3000` | 后端端口 |
| `DB_FILE` | `server/data/hr.sqlite` | SQLite 文件路径 |
| `JWT_SECRET` | 本地演示密钥 | 登录令牌签名密钥 |
| `APP_SECRET` | 本地演示密钥 | 身份证等敏感字段加密密钥 |
| `TOKEN_EXPIRES_IN` | `8h` | 登录令牌有效期 |

参考 `server/.env.example`。本项目未引入 `dotenv`，如需使用变量，请在启动终端中设置，或由部署环境直接注入。

## 5. 已实现功能

### 登录与角色

- 管理员、HR、普通员工三种角色。
- 登录后菜单和数据范围按角色动态隔离。
- 普通员工访问管理端接口统一返回 `403`。
- 登录令牌通过 `Authorization: Bearer <token>` 传递。

### 组织与员工

- 部门树、上下级关系、负责人、部门人数和职位数。
- 职位新增、编辑、筛选、分页和排序。
- 删除部门前检查下级部门和关联员工；删除职位前检查关联员工。存在关联时返回明确原因。
- 员工档案新增、编辑、调岗、离职、删除、分页、搜索、筛选和排序。
- 员工 CSV 导入逐行校验，返回具体行号与字段；任一行错误时整批不写入。
- CSV 导出带 UTF-8 BOM，Excel/WPS 打开中文不乱码。

### 员工自助

- 查看本人档案。
- 修改手机号、邮箱、地址、紧急联系人。
- 查看本人月度考勤。
- 查看本人工资条。

### 考勤与请假

- 月度考勤汇总、筛选、排序和维护。
- 请假类型、起止日期、事由和自动天数计算。
- 状态机：`草稿 → 待审批 → 已通过 / 已驳回`，草稿和待审批状态可取消。
- 禁止跳过状态、禁止审批自己的申请。

### 薪酬

- 按月批量生成工资单草稿。
- 维护基本工资、绩效奖金、社保公积金、个税、其他扣款和实发工资。
- 状态机：`草稿 → 已确认 → 已发放`，确认后禁止修改金额。
- HR/管理员可查看全员薪酬；员工只能查看本人数据。
- 薪酬修改、确认、发放均写审计日志。

### 系统管理

- 用户与角色管理，关联员工档案。
- 账号启用/停用、角色调整、密码重置。
- 系统始终保留至少一个启用管理员。
- 管理员审计日志查询与 CSV 导出，日志不允许修改或删除。
- 一键重置演示数据。

## 6. 安全与数据保真设计

- 密码使用随机盐 + `scrypt` 哈希，禁止明文和 MD5。
- 身份证号使用 AES-256-GCM 加密保存，接口按角色解密返回。
- 薪资和身份证字段按角色做字段级权限控制。
- 所有业务接口默认鉴权；仅登录接口公开。
- 所有 SQL 值均通过 SQLite 预编译参数绑定，排序字段只允许服务端白名单。
- 删除、批量导入、权限变更、薪资修改等关键操作写入审计日志。
- 前端对危险操作进行二次确认；后端仍会独立校验，不能靠绕过页面执行非法状态跳转。
- 统一错误响应格式：

```json
{
  "success": false,
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "员工资料校验失败",
    "details": [
      { "field": "employeeNo", "message": "工号不能为空" }
    ]
  }
}
```

成功响应统一为：

```json
{
  "success": true,
  "data": {},
  "meta": {
    "page": 1,
    "pageSize": 10,
    "total": 1,
    "totalPages": 1
  }
}
```

## 7. 主要 API

所有接口均以 `/api` 开头，完整路径应以服务端实际路由为准。

| 模块 | 接口示例 | 权限 |
|---|---|---|
| 登录 | `POST /api/auth/login` | 公开 |
| 当前用户 | `GET /api/auth/me` | 已登录 |
| 工作台 | `GET /api/dashboard` | 已登录，按角色返回 |
| 员工 | `/api/employees` | HR / 管理员；自助接口为已登录员工 |
| 部门 | `/api/departments` | HR / 管理员 |
| 职位 | `/api/positions` | HR / 管理员 |
| 考勤 | `/api/attendance` | 已登录，员工仅本人 |
| 请假 | `/api/leaves` | 已登录，员工仅本人；审批为 HR / 管理员 |
| 薪酬 | `/api/payrolls` | 已登录，员工仅本人；维护为 HR / 管理员 |
| 用户权限 | `/api/admin/users` | 管理员 |
| 审计日志 | `/api/admin/audit-logs` | 管理员 |

## 9. 常见问题

### 页面提示“无法连接后端服务”

确认后端终端已执行 `npm run dev`，并监听 `http://127.0.0.1:3000`。前端不会无限转圈：请求失败后列表会显示错误和“重新加载”按钮。

### 端口被占用

在对应启动终端设置端口：

```bash
# 后端改为 3100，同时需将 web/vite.config.js 的代理目标改为 3100
$env:PORT=3100   # PowerShell
npm run dev
```

macOS / Linux:

```bash
PORT=3100 npm run dev
```

### `node:sqlite` 不可用

通常是 Node 版本过低。请升级到 Node.js 22.5 以上，推荐 Node.js 24 LTS。

### 重置命令无法删除数据库

先停止正在运行的后端服务，再执行 `npm run reset-db`。如果只需要恢复演示数据，也可以使用管理员页面的重置入口。
